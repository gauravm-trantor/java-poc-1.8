- `rejectedBatchIsNotPublished:91 IllegalState No pending approval` (run 6): the same gap seen by `approve`.

So the gap has two halves, not one: `WAITING_APPROVAL` and `FAILED`.

### What the change really does

The cause. Ingest and Spark run in the Activiti job executor, inside a database transaction. The audit store (HBase, or the in-memory store in tests) is not part of that transaction. `SparkJobDelegate` writes `WAITING_APPROVAL`, and `RunFailure.mark` writes `FAILED`, while the transaction is still open. The approval task is created, or the run is ended, only when it commits. A client polling `status` can see the new status first and act too early.

The fix this card needs: the two statuses are written only after the transaction commits (for example with an Activiti transaction listener on `COMMITTED`), so a status a client sees is always true in the engine. What it keeps: the statuses, their order, the error text, the BPMN file, the HBase table layout and every existing test. A real client gains: approve at once after `WAITING_APPROVAL` no longer gets "No pending approval".
