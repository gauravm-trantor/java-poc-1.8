# SBJ17-2 Add a pipeline that runs the tests

Card on Relay: SBJ17-2. Branch: `card/SBJ17-2-pipeline`. Part of the goal SBJ17-1.
Standing facts: `.prime/facts.md` in the programme folder.

## Assess, the card lead, 2026-11-27

### What the card asks

Add a GitHub Actions workflow that builds every module on JDK 8 and runs `mvn clean test` and the UI tests on each pull request and on main. Main can then require it before merging. Today the repository has no `.github` folder and no pipeline.

### Change map

| What | Where |
|---|---|
| New file (the whole change) | `.github/workflows/ci.yml` (name to be fixed in Plan) |
| Maven build, entry point | `pom.xml` (parent; modules `common`, `spark-job`, `workflow-app`). Java 1.8, Scala 2.11.12, surefire 2.22.2, jacoco 0.8.12 |
| UI build, entry point | `ui/package.json`, `ui/angular.json` (Angular 20, Karma, Jasmine). Needs Node 20.19 or newer and Chrome |
| Tests that need a live service | `spark-job/src/test/scala/com/example/salesbatch/spark/SalesAggregatorHBaseTest.scala` (2 tests). It skips itself when ports 2181, 16000 and 16020 on localhost do not answer |
| HBase used locally | `docker/local/docker-compose.yml`, service `hbase`, image `harisekhon/hbase:1.4`, started by `docker/local/start-hbase.sh` with `hbase-server-site.xml` |
| Not touched | every source, pom and test file (never_touch and standing answer SA-2) |

### The application's folder and test commands

- Folder: the repository root `java-poc-1.8/` (Maven parent) and `ui/` (Angular).
- Java and Scala: `mvn -B clean test` from the root (README section 7).
- UI: `cd ui && npm ci && npx ng test --watch=false --browsers=ChromeHeadless` (README section 7 adds `--code-coverage`).

### Baseline, before the change

Run on a fresh clone of `main` (6e67fdd) in the scratch folder, on this laptop: Windows 11, Temurin 1.8.0_512, Maven 3.9.9, Node and Chrome 158. Logs are in `<programme>/.prime/tmp/SBJ17-2/` (`baseline-local-mvn.log`, `baseline-local-mvn-all.log`, `baseline-ui-test.log`).

| Suite | Run | Pass | Fail or error | Skipped |
|---|---|---|---|---|
| `common` | 30 | 30 | 0 | 0 |
| `spark-job` | 7 | 5 | 2 errors | 0 |
| `workflow-app` | 30 | 30 | 0 | 0 |
| Maven total | 67 | 65 | 2 | 0 |
| UI (Karma, ChromeHeadless) | 25 | 25 | 0 | 0 |

The 2 errors are the two `SalesAggregatorHBaseTest` tests. On this laptop something answers on ports 2181, 16000 and 16020, so the test does not skip, but the region server drops the connection (`RetriesExhaustedException ... host.docker.internal/127.0.0.1:16020`). This is the laptop's half-running HBase, not the code. A plain `mvn clean test` stops at `spark-job`, so `workflow-app` was counted with `-Dmaven.test.failure.ignore=true`.

What this means for the pipeline: a GitHub runner has no HBase, so these 2 tests will be skipped and the pipeline will show 65 passed and 2 skipped, not 67 of 67. The programme's deliverable says 67 of 67. To run them, the pipeline needs an HBase service. That is a decision for Plan (below).

No Linux container run was made in Assess: the Docker command needed an approval this run did not have. The first pipeline run in Test design is the Linux baseline.

- Second run, on a probe diff that only adds `.github/workflows/ci.yml` (`probe-ci.diff`): class `ci`, 1 file, no dependents, verdict **proceed with review**. It is not "proceed" only because there is no codebase assessment and no pipeline yet, which is what this card adds.

Verdict taken: proceed with review.

### Slice

One slice. One new file of well under 400 lines, one pull request, and a person can try it: open the pull request and see the checks run and pass. No split proposed.

### Decisions a person will need in Plan, each with a default

1. Criteria. Default set, to be asked for word for word:
   - AC1. A GitHub Actions workflow runs on every pull request to main and on every push to main.
   - AC2. It builds every Maven module on JDK 8 (Temurin) and runs `mvn -B clean test`; the run fails when any test fails.
   - AC3. It runs the UI tests headless in Chrome on Node 20.19 or newer; the run fails when any UI test fails.
   - AC4. The two HBase tests run against an HBase service in the pipeline and do not skip.
   - AC5. No existing source, pom or test file changes.
2. HBase in the pipeline. Choices: (a) run an HBase service container in the job so all Maven tests run (default; it matches the 67 of 67 deliverable); (b) let the 2 tests skip and say so in the run summary. With (a) the pipeline is slower and depends on the old third-party image `harisekhon/hbase:1.4`, the same one `docker/local` uses.
3. Requiring the check on main. A repository setting (branch protection). Default: the person turns it on after the merge; the card file will give the exact check name. The agent does not change merge rules.
